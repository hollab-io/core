# MeetingFactory

Unified meeting contract with an event-driven lifecycle and a commitments-only proposal/objection audit trail. One clone per organization, set as the `governanceProcess` on RoleRegistry — so the proposal lifecycle defined here is the **sole path** to structural change.

The contract does not model IDM rounds (clarifying questions, reactions, integration). Those live in the meeting room. What it commits to is: who proposed what, who objected, who adopted or discarded, and when each step happened. See `specs/05-governance-process.md` ("On-chain Commitments Surface").

**Source:** `packages/contracts/src/contracts/MeetingFactory.sol`

## Meeting Lifecycle

```solidity
function startMeeting(uint256 orgId, MeetingKind kind) external returns (uint256 meetingId);
function endMeeting(uint256 meetingId, uint256 orgId, MeetingKind kind) external;
```

`MeetingKind` is `Tactical` (0) or `Governance` (1). Starting requires org membership; ending requires org admin.

## Recording Tactical Outputs

```solidity
function recordOutput(
    uint256 meetingId,
    uint256 orgId,
    OutputType outputType,   // 0=NextAction, 1=Project, 2=Request, 3=Information
    string calldata description,
    address assignedTo,
    uint256 roleId
) external returns (uint256 itemId);
```

| Type | Name        | Description                              |
| ---- | ----------- | ---------------------------------------- |
| 0    | NextAction  | A concrete next step assigned to someone |
| 1    | Project     | A multi-step outcome to track            |
| 2    | Request     | A request for another role               |
| 3    | Information | Shared context for the circle            |

## Proposal Lifecycle

Structural changes flow through a four-step lifecycle: `createProposal` → (optional `raiseObjection` / `resolveObjection`) → `adoptProposal` or `discardProposal`. There is no `executeGovernance` shortcut — adopt is the only path that writes to the RoleRegistry.

```solidity
function createProposal(
    uint256 orgId,
    uint256 circleId,
    uint256 proposerRoleId,   // 0 if proposer is not a role lead
    bytes32 tensionHash,       // content-address of off-chain tension text
    ChangeType changeType,
    bytes calldata changeData  // ABI-encoded change payload
) external returns (uint256 proposalId);

function raiseObjection(uint256 proposalId, bytes32 concernHash)
    external returns (uint256 objectionId);

function resolveObjection(uint256 objectionId) external;
    // callable by the original objector (withdrawal) or the circle facilitator (§5.3.3 dismissal)

function adoptProposal(uint256 proposalId) external returns (uint256 resultId);
    // org admin only; reverts if open objections remain or proposal has expired

function discardProposal(uint256 proposalId) external;
    // org admin only

function discardExpiredProposal(uint256 proposalId) external;
    // permissionless — anyone can discard proposals older than MAX_PROPOSAL_AGE (14 days)
```

Any org member can create a proposal or raise an objection. Only org admins can adopt or discard. The contract **enforces** that all objections must be resolved before adoption (`_openObjectionCount == 0`). Proposals expire after 14 days and can be permissionlessly discarded via `discardExpiredProposal`.

### ProposalRecord fields

| Field            | Notes                                                             |
| ---------------- | ----------------------------------------------------------------- |
| `id`             | Proposal id (auto-incremented per clone)                          |
| `orgId`          |                                                                   |
| `circleId`       | Circle the change targets (anchor = 0)                            |
| `proposer`       | `msg.sender` at create time                                       |
| `proposerRoleId` | 0 if the proposer is not currently a role lead                    |
| `tensionHash`    | `bytes32` — sha2-256 digest of an IPFS CIDv0, or keccak256 inline |
| `changeType`     | `HolacracyTypes.ChangeType` (CreateRole, AmendRole, Election, …)  |
| `changeData`     | ABI-encoded payload, decoded by `_applyChange` on adopt           |
| `status`         | `Draft` → `Adopted` or `Discarded` (MVP uses these three)         |
| `submittedAt`    | uint64 timestamp                                                  |
| `resolvedAt`     | uint64 timestamp, set on adopt or discard                         |

### ObjectionRecord fields

| Field         | Notes                                                         |
| ------------- | ------------------------------------------------------------- |
| `id`          | Objection id                                                  |
| `proposalId`  | Proposal the objection targets (must be Draft when raised)    |
| `objector`    | `msg.sender` at raise time                                    |
| `concernHash` | `bytes32` — content-address of the objection text (off-chain) |
| `status`      | `Raised` → `Resolved` (MVP uses these two)                    |
| `raisedAt`    | uint64 timestamp                                              |
| `resolvedAt`  | uint64 timestamp, set on resolve                              |

The encoding for `changeData` per `ChangeType` lives in the NatSpec of `MeetingFactory._applyChange`. For example:

```text
CreateRole:  abi.encode(circleId, name, purpose, domains[], accountabilities[])
AmendRole:   abi.encode(roleId,   name, purpose, domains[], accountabilities[])
RemoveRole:  abi.encode(roleId)
Election:    abi.encode(roleId, newLead, previousLead)
```

## Linking Proposals to Meetings

Governance proposals can be linked to meetings for traceability:

```solidity
function linkProposal(uint256 meetingId, uint256 orgId, uint256 proposalId)
    external returns (uint256 itemId);
```

## Events

All lifecycle transitions emit events consumed by the Ponder indexer:

-   `MeetingStarted(meetingId, orgId, kind, startedBy, timestamp)`
-   `MeetingEnded(meetingId, orgId, kind, endedBy, timestamp)`
-   `MeetingOutputRecorded(meetingId, itemId, orgId, outputType, assignedTo, roleId, description)`
-   `MeetingProposalLinked(meetingId, itemId, orgId, proposalId)`
-   `ProposalCreated(proposalId, orgId, circleId, proposer, proposerRoleId, tensionHash, changeType, changeData)`
-   `ProposalAdopted(proposalId, orgId, resultId, adoptedBy)`
-   `ProposalDiscarded(proposalId, orgId, discardedBy)`
-   `ObjectionRaised(objectionId, proposalId, objector, concernHash)`
-   `ObjectionResolved(objectionId, proposalId, resolvedBy)`

The five proposal/objection events are fully event-sourced — the indexer can persist the full row without any contract reads.
